# 段階 1: 設計議論

## 判断点の出し方

- 自明な判断、検討に値しない案だと思えば引っ込める
- 判断点は user が理解しやすい形 (= 2-4 案の比較 table) で提示
- 複数の案がある場合は最初に各１行程度で列挙してから議論を始める
- 案を出す時は trade-off, 懸念も併記する
- 推奨があれば明示する

## 議論の進め方

- user と意見が食い違う場合、鵜呑みにせず自分の判断で議論を行う (= 中立性プロトコル: 事実誤認の指摘 → 訂正、ただし総合判断は別途検討)
- 意見が変える場合「なぜ変えたか」を明示する (= 「前段で X と言ったが、schema が core にあるという前提を見落としていた、訂正する」)
- 動かす前に抽象を積み上げない、動作検証可能な粒度まで詰める
- design.md 等のドキュメントを勝手に書かない、書くなら先に user 合意を取る

## 不明点が出たら

- 議論中に「これは設計判断が必要, user 判断必要」と気付いたら、即座に手を止めて確認しろ。議論を進めながら裏で別判断を勝手に決めるな
- 段階 0 で確認漏れの code, knowledge があると気付いたら、議論を中断して再確認しろ

## 実装計画

- 判断点が全て確定した時点で実装計画に進む
- 実装計画を user が承認したら実装に進む
